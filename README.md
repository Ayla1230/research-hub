# Research Hub · 研究進度中樞

<p align="center"><b>本機執行的論文進度管理系統。</b><br>
從研究主題到口試發表，一條節點流程管理整個研究；研究問題、變數、文獻、資料庫、本機資料夾、MCP 智能體與 Python 分析程式集中在同一個平台。</p>

<p align="center"><b>繁體中文</b> · <a href="README.en.md">English</a></p>

## 快速開始

只需要 Python 3.10 以上，**不需安裝任何套件**（只用標準函式庫）。

```bash
./start.sh            # macOS / Linux，於專案根目錄執行
start.cmd             # Windows
./start.sh --demo     # 以範例資料（TAM 研究）體驗
./start.sh --lang en  # 新工作區預設英文介面與待辦事項（預設待辦事項以建立時的語言寫入，之後可自行改寫）
```

開啟 <http://127.0.0.1:8770/>。根目錄 `/` 即為儀表板，`/zh/`、`/en/` 直接切換語言（右上角也可切換）。
**建議下載到自己電腦執行**：所有操作都在本機（`127.0.0.1`）完成，資料只在你電腦內部傳輸，不消耗對外網路流量；預設不載入任何網路字型。只有 OpenAlex 檢索與開啟外部資料庫連結會連網。

資料預設存在 `~/ResearchHub`（可用 `--data <資料夾>` 或環境變數 `RESEARCH_HUB_HOME` 指定），埠號可用 `--port` 或 `RESEARCH_HUB_PORT` 指定。

## 主要功能

| 區塊 | 說明 |
|---|---|
| **研究流程節點** | 儀表板以一列節點（01 → 10）呈現研究全程：研究主題、文獻探討、研究問題與假設、研究架構與變數、研究方法、資料蒐集、資料分析、結果與討論、論文撰寫、口試與發表。每個節點以圓環顯示進度、狀態與待辦完成數。節點可新增、改名、排序、刪除，以對應系所或實驗室的流程圖。 |
| **階段工作區** | 點選任一節點即展開該階段：狀態（未開始／進行中／審閱中／已完成／受阻）、進度滑桿、起訖日期與逾期提醒、自動儲存的筆記、待辦清單、檔案上傳（拖曳即存入系統目錄）、連結資源，以及該階段的專屬模組（文獻、RQ、變數與架構、Python、寫作引用）。 |
| **研究核心** | 專門管理研究問題（RQ）、變數（自變數 X、依變數 Y、中介 M、調節 Z、控制 C）與文獻。每個變數都能連結相關論文並標示關係（支持、反駁、結果分歧、定義來源、量表來源、提及），未有文獻支持的變數會被標示提醒。 |
| **變數 × 文獻矩陣** | 一眼看出每個變數有哪些文獻支持，點選格子即可切換關係。 |
| **研究架構圖** | 依變數角色自動繪出 X → M → Y、Z 調節、C 控制的概念模型。 |
| **文獻管理** | OpenAlex 檢索並加入、匯入／匯出 BibTeX 與 RIS（依 DOI、引用鍵、標題自動略過重複）、閱讀狀態（候選／待閱讀／閱讀中／已讀完／排除）、評分、標籤、開啟本機 PDF。 |
| **整合中心** | 學術資料庫一鍵檢索（Google Scholar、Semantic Scholar、arXiv、PubMed、Scopus、Web of Science、華藝、臺灣博碩士論文系統，可自行新增，網址中以 `{q}` 代表關鍵字）；本機文獻資料夾掃描與匯入；MCP 工具設定；Python 程式資料夾與腳本執行；所有上傳檔案。 |
| **即時更新＋使用者確認** | 智能體完成任務、資料夾出現新檔案、背景追蹤找到相關新文獻時，變更會先進入「待確認更新」收件匣；使用者逐項勾選、核准後才寫入，確保進度追蹤正確。儀表板透過 Server-Sent Events 即時刷新。 |
| **動態紀錄與備份** | 每次變更記錄來源（使用者／智能體／資料夾監看）與時間；可匯出完整 JSON 備份與 BibTeX。 |

## 上傳與進度回報（v1.1）

每次上傳檔案都會開啟「上傳與進度回報」視窗（也可從首頁「上傳並回報進度」或各階段的「回報進度」開啟）：

1. **自動歸檔**：依檔名與資料夾名稱判斷所屬階段，例如 `analysis_regression.py` 歸到「資料分析」、`文獻探討_v2.docx` 歸到「文獻探討」。可在設定加入自訂規則（每行 `關鍵字 => 階段代號`），自訂規則優先。
2. **說明目前進度（必填）**：每次上傳都要寫下這次完成了什麼、卡在哪、下一步是什麼，會記錄在該階段的「進度日誌」。
3. **進度**：勾選完成的待辦後，進度依待辦完成比例自動計算（可在設定關閉），也可拖動滑桿手動指定。
4. **完成目標**：設定本階段的目標完成日與完成標準，以及論文最終完成日；首頁會顯示倒數。
5. **追蹤相關文獻**：送出後在背景搜尋相關新文獻，結果放進「待確認更新」，確認後才加入文獻庫。

**自動追蹤**：有開始與截止日期的階段，會比對「依時間應有的進度」與實際進度，在節點與階段面板標示「落後 N%」或「超前 N%」。

### 文獻來源（免費、每日額度午夜自動重置）

| 來源 | 方式 | 需要金鑰 |
|---|---|---|
| OpenAlex | 官方免費 API | 否 |
| Wiley | 透過 Crossref 免費 API，篩選 Wiley 出版文獻 | 否 |
| Semantic Scholar | 官方免費 API | 否 |
| Web of Science | Clarivate Starter API | 是（Clarivate 開發者網站有免費方案，或洽學校圖書館） |
| Google Scholar | 沒有官方 API，會在新分頁開啟搜尋（不自動抓取，以免違反使用條款） | — |

### AI 助理（選用）

在設定選擇 Google Gemini（免費額度）、Groq、OpenRouter 免費模型、本機 Ollama，或任何相容 OpenAI 格式的服務。AI 只在你按「AI 解讀進度」時呼叫：讀你的進度說明，建議進度百分比、已完成的待辦與檢索關鍵字，由你確認後才送出。金鑰只存在本機，不會顯示或回傳到頁面。

### 每日用量

整合中心的「今日用量」顯示各來源與 AI 今天用了幾次與多少 token、上限，以及距離重置的時間。上限可在設定調整，達到上限時當天會停止呼叫，午夜（本機時間）自動重置。

## 從自己的文章產生研究架構圖

在「研究核心 → 研究架構圖」按「從我的文章產生」，貼上或上傳你寫的文章（`.docx`、`.txt`、`.md`、`.tex`）：

- **規則辨識（免費、離線）**：找出像「H1：知覺有用性對使用意圖有正向影響」「知覺易用性正向影響知覺有用性」「信任調節知覺有用性與使用意圖之間的關係」「使用態度在知覺有用性與使用意圖之間具有中介效果」這類中英文假設句，自動判斷自變數 X、依變數 Y、中介 M、調節 Z。
- **AI 解讀（選用）**：文章沒有整理成假設句時更準確，計入今日用量。
- **先檢查再套用**：預覽圖、變數（可改符號、名稱、角色，與既有變數同名時自動沿用）與假設路徑都可以逐項取消，按「套用到研究核心」才寫入。
- **研究架構圖**依假設路徑繪製：線上標示假設編號與正負方向，負向為紅色虛線，調節變數的箭頭指向它調節的路徑，跨欄的路徑會從上方繞過其他方框。也可以手動「新增假設路徑」。
- **下載 SVG**：乾淨的向量圖（不含文獻數與 RQ 標記），可直接放進論文或簡報。

## 自動產生 PowerPoint 簡報

首頁「產生簡報」（或「論文撰寫」階段）會開啟 **簡報設計指令** 視窗：

1. **設計指令**：用一兩句話描述，例如「給指導教授的進度報告，10 頁，深藍色，標題用宋體、內文用微軟正黑體，不要文獻」，按「依指令調整」會自動套用配色、字型、用途、頁數、語言、尺寸與要／不要的頁面。可選擇讓 AI 依指令撰寫每頁重點與講稿（計入今日用量）；不使用 AI 時，重點與講稿由系統依你的資料自動整理。
2. **用途**：指導教授進度報告、論文口試、研討會發表，各有預設頁面。
3. **頁面內容**：封面、進度總覽、研究問題、研究架構圖、研究假設、變數定義表、文獻回顧、近期進度、下一步、結尾 Q&A，可自由勾選。
4. **版面與字型**：五種配色；標題與內文字型可分開選擇：
   - 思源宋體（開源明體）Noto Serif TC
   - 新細明體 PMingLiU（Windows 內建明體）
   - 微軟正黑體 Microsoft JhengHei
   - 思源黑體（開源）Noto Sans TC
   - 標楷體 DFKai-SB、蘋方 PingFang TC
   字型同時寫入每段文字與簡報主題，之後在 PowerPoint 新增的文字也會使用相同字型。開源字型需先安裝在播放簡報的電腦上（視窗中附下載連結）。
5. **匯出 PowerPoint**：產生 `.pptx`（16:9 或 4:3），研究架構圖以 PowerPoint 原生圖形繪製，可直接在 PowerPoint 裡修改；可同時存一份到「口試與發表」階段。

簡報在瀏覽器中產生（內建 PptxGenJS，MIT 授權，不需網路）；只有勾選 AI 撰寫時才會呼叫你設定的 AI 服務。

## 智能體與 MCP

Research Hub 內建 MCP 伺服器（stdio，標準函式庫實作）。在「整合中心 → MCP 工具與智能體 → 顯示指令」取得含金鑰的設定，例如 Claude Code：

```bash
claude mcp add research-hub -- python -m research_hub mcp --url http://127.0.0.1:8770 --token <agent token>
```

提供的工具：`get_overview`、`get_schema`、`list_items`、`propose_changes`、`report_stage_progress`、`propose_papers`、`check_proposals`。
**所有寫入類工具都只會建立提案**，不會直接修改資料。智能體可搭配你自己的文獻檢索 MCP（記錄在整合中心），把找到的論文以 `propose_papers` 送進收件匣並連結到變數或 RQ。

不使用 MCP 時，也可用指令列或 HTTP 送出提案：

```bash
python -m research_hub propose changes.json --token <agent token>
curl -X POST http://127.0.0.1:8770/api/agent/proposals -H "Authorization: Bearer <agent token>" \
     -H "Content-Type: application/json" -d '{"title":"文獻探討完成","ops":[{"op":"update","entity":"stage","match":{"key":"literature"},"data":{"status":"review","progress":100}}]}'
```

審閱時若取消勾選某個「新增」項目，引用它的連結會自動一起取消；若提案建立後該項目已被你修改，會顯示衝突提醒。智能體附加的筆記以 `append` 在核准當下接在最後，不會覆蓋你較新的內容。

提案格式（`ops`）：`create`／`update`（可加 `"append": {"notes": "…"}`）／`delete`（`entity` 為 `stage`、`task`、`rq`、`variable`、`paper`、`resource`），以及 `link`／`unlink`（`rq_variable`、`rq_paper`、`variable_paper`）。同一批次中可用 `"ref": "p1"` 建立物件，再以 `"$p1"` 引用。

## Python 程式

在設定中指定後續開發的 Python 專案資料夾，整合中心會列出其中的 `.py`／`.ipynb`。若勾選「允許從儀表板執行 .py 腳本」，可直接執行並查看輸出（使用目前的 Python、工作目錄為程式資料夾、有逾時限制；預設關閉）。

## 安全與資料

- 只監聽 `127.0.0.1`，並檢查 Host 標頭（防 DNS rebinding）；系統沒有登入機制，請勿直接暴露到網際網路。
- 儀表板的每個請求都需頁面載入時取得的 token，其他網站無法跨站寫入。
- 智能體使用獨立、可重設的 agent token，只能讀取與提出變更。
- 只會讀取／開啟設定中的資料夾（文獻資料夾、程式資料夾）與上傳目錄內的檔案。
- 工作區內容：`hub.sqlite3`（所有結構化資料）與 `uploads/`（上傳檔案，依階段分資料夾）。
